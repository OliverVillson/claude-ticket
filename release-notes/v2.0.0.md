## salu v2.0.0

Update: `salu update`, then `salu --version` and `salu doctor`. Coming from v1.2.0: `docs/migrating-to-v2.md`.

v2 is co-working on one Claude Team or Enterprise seat per person. A project with no roster runs exactly as
in v1.2.0, and the old shared signing key keeps working until an admin retires it.

### Teams, seats and keys
- **Roster and seats:** `salu team` and `salu seat` keep who is on a project and which Claude seats it can use. The first person added owns the project. A seat is a name; it holds no secret.
- **Seat logins:** `salu kernel login --seat <id>` saves one seat's token on the box. A ticket on that seat runs in a container of its own for that project and seat and reaches the model only through that seat's proxy. A seat with no login refuses the ticket; it never falls back to the box login or another seat.
- **Per-person keys:** `salu team key <name>` makes a personal signing key. The box knows who sent every file, and a removed or revoked person's files are refused. `salu team key --retire-shared` stops accepting the old shared key.
- **Roles:** the admin owns the project; members add tickets, reply, and resolve or reopen their own. The shared key counts as an unnamed member, never an admin. Ticket ownership comes from the signature, not the file: the `by-<name>` label is added only from a verified personal key.
- **Heads up, visible change from v1.2.0:** tickets sent with the shared key now show as unnamed (they used to carry the sender's `SALU_USER`). Once any member has a personal key, unsigned files are refused. Keys are HMAC secrets stored on the box: revocation and attribution, not protection from someone who can read the box database.
- **Team views:** `by` and `seat` columns in `salu list` and the TUI, each seat's meter, and `salu team invite <name> [--with-key]` prints one block a friend pastes to join. The phone shows the same line.

### Scheduler
- **`salu sched on`** now holds the queue when the 5-hour window is full or rejected even with no learned estimate; `SALU_SCHED_MARGIN` and `SALU_SCHED_RESERVE` override the margins.
- **Seat-aware:** with seats, a ticket starts on the seat that has room, and `salu sched` says why the others did not. `salu usage` shows one meter per seat and names a dead login.
- **Lending spare seat time (off by default):** a seat's owner can lend a capped slice (`salu seat lend`), every borrowed ticket is logged (`salu seat lent`). Only named members borrow: a ticket with no named requester (shared key, made on the box, or a `by-` label naming nobody on the team) never borrows and runs on the project's ownerless seats or the admin's seat, as in v1. **The subscription terms for sharing seat time were not checked at the source.** Lending is the lender's choice and responsibility.

### Safety and platforms
- **Safe-kernel hardening:** a gVisor release override now needs its own checksum; a per-project egress allow-list (`SALU_SANDBOX_DOMAINS_<SLUG>`); a warning when the storage backend cannot enforce the per-container disk cap; a size guard on the control repo (`SALU_CONTROL_MAX_MB`, default 128).
- **macOS:** the release workflow runs the compiled macOS binary and attacks the worker fence on a real arm64 and a real x64 Mac before publishing.
- **Phone:** `ios/device.sh` for a real iPhone, a "Make a token for this repo" flow, and ntfy pushes that open the ticket.

### Not verified
- Per-seat usage has not been checked against a live Team login.
- The seat scheduler has not run on a real two-seat box; it was tested with fake meters and fake logins.
- The scheduler's real-window check on the box (`scripts/sched-window-run.sh`), the macOS fence run on the owner's Mac, the real iPhone build and the safe-kernel box checks are still waiting on the owner.
- The Swift changes (team rows, personal keys on the phone) were not compiled. The phone still signs with the shared key, so keep the shared key until the phone supports personal keys.
- Subscription terms for sharing seat time: not checked.
