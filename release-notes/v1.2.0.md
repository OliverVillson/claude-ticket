## salu v1.2.0

Update: `salu update`, then `salu --version` and `salu doctor`.

### Your own always-on box, set up from your Mac
- **`salu box add`** sets up a Linux box over ssh (home laptop or rented VPS) and pairs it with this Mac. `salu box status | update | login | list` look after it. The box installer is one signed bundle with the salu binary, the installer scripts and the kernel recipe (`install-box.sh`, detached and resumable).
- **`salu new --on <box>`** sends a ticket to a box; a box holds the login once (`salu box login`, `salu box relogin`) and runs the tickets in its kernel.
- **Control channel:** the Mac and the box talk through a private git repo with signed, sealed messages (`docs/control-channel.md`). The box pins github.com's host key for its deploy key.
- Short install URL, a quickstart (`docs/quickstart.md`) and an Ubuntu prep guide (`docs/ubuntu-prep.md`).

### Live tickets and co-working
- **Live tickets (#86):** a ticket added, replied to or resolved in the TUI on a box project now reaches the box right away (it used to be saved locally only). The box checks its inbox every 3 s (was 30) and open TUI windows refresh every 4 s, so a ticket sent from the phone shows as running on the Mac in about 10 s.
- **Co-working (#85):** every ticket records who added it (`SALU_USER`, else your login name); the box labels it `by-<name>`, and every other computer on the box gets a copy, so a few trusted people see one list. Tickets still run on the box's one login. How to join: `docs/coworking.md`.

### Safe kernel demo
- **`salu kernel demo [--slow]` (#88):** starts a throwaway container exactly the way a ticket's is started, then runs 17 hostile attempts as root inside it (read the Claude login, read a file on the box, follow a symlink out, mount, write to system folders, reach cloud metadata, LAN and Tailscale addresses, skip the proxy) and prints what the agent saw and whether the boundary held. Exit code 1 if anything gets through. `--slow` types the commands and pauses for screen recording. Needs the container kernel (`salu kernel setup`). Honest limit printed at the end: the proxy socket still lets the agent make model calls on the same quota.

### Signed releases
- Every release is signed with an ed25519 key. The public key is built into salu (`src/release/key.ts`). The box's update handler and installer verify `SHA256SUMS` and the installer's signature before running anything and refuse an unsigned or altered release.
- `salu release pubkey | sign <tag> | verify <folder>`. Signing is done by the owner on their Mac after the release workflow has run.
- Heads up: a box built before this key was pinned cannot verify a release. Reinstall it once from this release.

### Tickets and the phone
- iPhone app (SwiftUI, `ios/`, builds in Xcode): the salu look and the dog, inbox, tickets as threads with checklist, decisions and outputs, keep chatting, sample-data mode, signing key in the Keychain. It is not on the App Store: you build it yourself (`ios/README.md`).
- The rate-limit test no longer depends on the calendar.

### Not verified
The box setup, the control channel and the installer are tested against fakes and harnesses, not yet on a real box end to end. The macOS binaries are checksum-verified only.
